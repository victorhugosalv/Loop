LOOP NO MERCY REGRAS

O jogo da programação: a mesa é o computador, e cada carta é uma linha de código.

BNCC Computação · 6º ano · Pensamento Computacional
Objetivo Preparação Tipos de dados Sua vez Cartas de ação Curingas Regras especiais Exemplo Desafio Cola rápida BNCC

Objetivo

Seja o primeiro a terminar a execução, ou seja, zerar sua mão. Outra forma de vencer é ser o último processo rodando depois que todos os outros sofreram Crash.

A ideia

A mesa funciona como um compilador. Cada jogador adiciona uma linha de código (descarta uma carta) que precisa ser compatível com a anterior. Se ninguém consegue processar a informação, o sistema acusa erro e o jogador precisa alocar mais memória (comprar cartas).

Jogo base
UNO Show ’em No Mercy (168 cartas)
Jogadores
2 a 6 por baralho, com grupos de 4–6 alunos
Sua mão
= sua memória RAM
Pilha de compras
= memória disponível

Preparação

  1. Escolha quem vai distribuir e embaralhe. O baralho é grande: se precisar, dividam para embaralhar.
  2. Dê 7 cartas para cada jogador. Essa é a memória inicial de cada processo.
  3. Coloque o resto virado para baixo no centro. Essa é a PILHA DE COMPRAS.
  4. Vire a carta de cima para formar a PILHA DE DESCARTE (a primeira linha do programa). Se for uma carta de ação, vire outra.
  5. Quem está à esquerda de quem distribuiu começa, e o jogo segue no sentido horário.
🏷️ Material de apoio: cole nas cartas adesivos com o tipo de dado e o nome do comando, ou deixe a cola rápida na mesa.

Tipos de dados (as cores)

Cada cor é um tipo de dado. O número da carta é o valor, escrito do jeito que aquele tipo representa:

●7intInteiro
✦7.0floatDecimal
■"7"StringTexto
▿falsebooleanLógico

Booleano: carta verde com número par vale true, e com número ímpar vale false.

Quando posso jogar? (Type Checking)

Sua carta é compatível se tiver o mesmo tipo (cor), o mesmo valor (número) ou o mesmo comando (símbolo).

💬 Pergunta pra turma: um 🔴 7 e um 🔵 "7" são iguais para o computador? No jogo pode, mas em muitas linguagens 7 == "7" dá erro ou false. Isso é conversão de tipos.

Os símbolos ● ✦ ▿ ■ já vêm impressos nas cartas para jogadores daltônicos.

Sua vez

Na sua vez, execute este algoritmo. Ele tem sequência, seleção (se) e repetição (enquanto):

se (tenhoCartaCompativel()) {
    jogar(carta)            // adiciona uma linha ao código
} senão {
    enquanto (!cartaCompativel(topo)) {
        topo = comprar()     // aloca memória
    }
    jogar(topo)
}
se (mao.tamanho == 1) gritar("PRINT!")
se (mao.tamanho >= 25) crash()

Se a pilha de compras acabar, embaralhe a pilha de descarte (menos a carta do topo) para formar uma nova.

O próximo jogador (o afetado) escolhe um tipo. Ele revela cartas da pilha, uma por vez, enquanto não aparecer aquele tipo (curingas não contam). Fica com todas as cartas reveladas e perde a vez. O jogo segue no tipo escolhido.

faça {
    carta = comprar()
} enquanto (carta.cor != tipo ou carta.ehCuringa)
perderVez()

Regras especiais

🖨️ PRINT!

Quando ficar com 1 carta, grite “PRINT!” (a saída no terminal). Se outro jogador gritar antes de você, e antes de o próximo começar a vez, é Erro de Sintaxe: compre 2 cartas.

📚 Stack Overflow (empilhamento)

Se alguém jogar um Bug (+2, +4, +6, +10) em você, você pode empilhar jogando outro Bug de valor igual ou maior. As penalidades se somam e passam adiante. O primeiro que não conseguir empilhar sofre o Stack Overflow: compra tudo o que foi acumulado e perde a vez.

pilha = 0
enquanto (jogador.temBug(valor >= ultimo)) {
    pilha += jogador.jogarBug()
    jogador = proximo()
}
jogador.comprar(pilha)   // Stack Overflow!

💥 Crash do Sistema (Misericórdia)

Com 25 cartas ou mais na mão, a memória estoura: Crash (tela azul). O jogador está fora do jogo. As cartas dele ficam separadas até a pilha de compras acabar.

Como vencer

Vence quem jogar a última carta ou quem for o último processo rodando.

Pontuação (opcional)
  • Cartas numéricas: o próprio valor
  • Cartas de ação coloridas: 20 pontos
  • Curingas: 50 pontos
  • Cada jogador que sofreu Crash: +250 pontos
  • Vence quem chegar a 1000 pontos primeiro

Exemplo: a cascata de bugs

  1. Jogador A joga um 🔴 Bug Crítico +4 (tipo int).
  2. Jogador B empilha com um Curinga Bug Fatal +6 e faz um Casting para 🔵 String. A pilha agora vale 10.
  3. Jogador C, que já tinha 16 cartas, não tem nenhum Bug +6 ou maior. É Stack Overflow: ele compra as 10 cartas e perde a vez.
  4. C fica com 26 cartas (≥ 25). Crash do Sistema! C está fora do jogo.
// rastreando a execução
pilha = 4          // A: Bug Crítico
pilha = 4 + 6      // B: empilhou → 10
C.mao = 16 + 10    // = 26
se (C.mao >= 25) crash(C)  // 💥

Desafio pós-jogo: programe uma carta

Agora é a vez de vocês elaborarem o algoritmo. Em grupo, escolham uma carta ou regra e escrevam o código dela em pseudocódigo, Scratch ou Python. O código precisa usar pelo menos:

Sequência
passos em ordem
Seleção
se / senão
Repetição
enquanto / para
Tipos de dados
int, float, String, boolean

Sugestões: Roleta Colorida · Stack Overflow · Garbage Collector · o turno completo · checar se uma carta verde é true ou false.

# exemplo em Python: Garbage Collector
mao = [("vermelho", 7), ("azul", 3), ("vermelho", 2)]
cor_gc = "vermelho"
nova_mao = []
for carta in mao:
    if carta[0] != cor_gc:
        nova_mao.append(carta)
print(nova_mao)   # [('azul', 3)]

Objetivo de aprendizagem

Jogando como um “compilador”, os alunos classificam valores em tipos de dados (inteiro, decimal, texto e booleano) e fazem type checking a cada jogada. Eles vivenciam com o corpo como sequência, seleção e repetição controlam o fluxo de um programa e como o mau gerenciamento de memória leva a um Crash. No desafio pós-jogo, elaboram esses algoritmos em uma linguagem de programação.
